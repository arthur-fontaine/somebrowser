# AGENTS.md — how to work on (and fork) this browser

This file is for coding agents and humans customizing the browser. Read it fully before editing.

## Posture

- **Everything is a feature.** Shell (`Shell/`) and Core (`Core/`) contain no feature names. A feature is
  a folder `Features/<Name>/` with `feature.json`, `Sources/`, `Tests/`, `README.md`.
- **Nothing is listed by hand.** `Package.swift`, the feature registry, branding and `main.swift` are
  generated by `./forkctl generate` from manifests. Never edit `Package.swift` or `Generated/`.
- **Forks customize through `Fork/`**, a directory upstream never contains. `git merge upstream/main`
  therefore cannot conflict on customizations.
- **Every feature has tests**, and they must pass: `./forkctl test` (all) or `./forkctl test <feature-id>`.
- Commit atomically (one logical change per commit, Conventional Commits).

## Where things are

| Path | What |
|---|---|
| `Core/Sources/Engine/` | Engine boundary: `BrowserEngine`, `EngineTab`, `EngineViewport`, `EngineHooks` |
| `Core/Sources/Model/` | `TabStore` (spaces, favorites, pinned/today, the tab tree), `BrowserWindowState` |
| `Core/Sources/Runtime/` | `BrowserRuntime` (composition root), `FeatureContext` (what a feature can touch) |
| `Core/Sources/Capabilities/` | Shared contracts (`SearchService`, `HistoryService`, `OmniboxProvider`…) |
| `Core/Sources/UI/` | Slots (`SlotID`) and `UIRegistry` — how features put views in the window |
| `Shell/` | NSApplication, native window, generated menu bar, settings window, automation socket |
| `Engines/<Name>/` | Engines (`engine.json` + sources): `WebKit`, `CEF` (Chromium) |
| `Features/<Name>/` | Features (see `./forkctl feature list`) |
| `Testing/` | `FakeEngine`, `TestHarness` for feature tests |
| `Tools/forkctl/` | The generator/validator/bundler and fork verbs |
| `Defaults/` | Upstream defaults: `fork.json` (brand, engine, settings), entitlements, icon |
| `Fork/` | Your fork's overrides (create it with any fork verb) |
| `docs/decisions/` | Architecture decisions (read 0001–0003 before touching engines) |
| `docs/recipes/` | Longer how-tos (an ungoogled CEF source build) |

## Recipes

| Task | Do this |
|---|---|
| Build / run | `./forkctl build` · `./forkctl run` |
| Test everything / one feature | `./forkctl test` · `./forkctl test sidebar` · `./forkctl test engine` |
| Chromium logs | run `build/<Name>.app/Contents/MacOS/<Name> --enable-logging=stderr --vmodule='*extension*=1'` |
| Rename the browser | `./forkctl rename "Kestrel" --bundle-id dev.me.kestrel` (the profile folder moves over on first launch) |
| Change the icon | `./forkctl icon path/to/1024.png` (hand-drawn small sizes sit next to it as `AppIcon-16.png`, `AppIcon-32.png`) |
| Swap the engine | `./forkctl engine list` · `./forkctl engine use webkit` |
| Use your own CEF build | pin it in `Fork/Engines/CEF/vendor.json`, then `./forkctl vendor cef` (`docs/recipes/ungoogled-cef.md`) |
| Remove / add back a feature | `./forkctl feature disable pip` · `./forkctl feature enable pip` |
| Create a feature | `./forkctl feature new reading-list` (upstream) or `--fork` (lives in `Fork/Features/`) |
| Replace an upstream feature | create it with `--fork`, set `"replaces": "<upstream-id>"` in its `feature.json` |
| Change a shortcut | `./forkctl shortcut tabs.close cmd+shift+x` (or `none`) |
| Change a default setting | `./forkctl setting search.engine '"kagi"'` |
| Check the project | `./forkctl validate` · `./forkctl doctor` |

## Writing a feature

1. `./forkctl feature new my-thing` → manifest, entry class, README, a passing test.
2. Declare **commands** (id, title, shortcut, menu, group) and **settings** (key, type, default) in
   `feature.json`. Ids are namespaced: `my-thing.*`. Menus, the command bar, shortcut settings and the
   settings window are generated from these.
3. In `activate()`:
   - `context.commands.handle("my-thing.do") { invocation in … }`
   - `context.ui.contribute(.sidebar / .overlay / "sidebar.footer" / …, id:) { window in SomeView() }`
   - `context.hooks.addUserScript(…)`, `handleMessages(named:)`, `addRequestFilter`, `addNavigationPolicy`
   - `context.events.subscribe(TabNavigated.self) { … }`
   - `context.capabilities.provide(SomeProtocol.self, impl)` to offer a service
4. **Never import another feature.** Talk through Core contracts (capabilities), events, slots or
   command ids (`commands.isHandled("x.y")` before running another feature's command).
5. Tests in `Tests/` with `TestHarness(features: [MyThingFeature.self], manifestDirectory: #filePath)`.
   Stub other capabilities with `harness.runtime.capabilities.provide(…)` (pass `activate: false` first).
6. Keep `README.md` current (purpose, how it works, capabilities, tests, how to remove).

`./forkctl validate` enforces: unique namespaced ids, shortcut collisions (after fork overrides),
capability graph, entry type exists, a `Tests/` dir per feature, no cross-feature imports, no hard-coded
product name (use `Brand.name`), no URLSession in features or engines (the browser's own requests go through
`context.fetch` / `hooks.fetch`, which Security Core logs).

## Running the real app in tests

Launch with `BROWSER_DATA_DIR=<tmp>` (isolated profile and settings: `<tmp>/settings.plist`) and `BROWSER_AUTOMATION_SOCKET=<path>`; send
newline-delimited JSON: `{"op":"open","url":…}`, `{"op":"navigate","url":…}`, `{"op":"run","command":"tabs.close"}`,
`{"op":"state"}` (tabs, windows, the app's memory footprint), `{"op":"eval","js":…}`, `{"op":"setting","key":…,"value":…}`,
`{"op":"views"}`, `{"op":"documentStart","js":…,"prefix":…}`, `{"op":"key","key":"f","modifiers":["cmd"],"keyCode":3,"page":true}`
(key windows only exist when the app is frontmost), `{"op":"click","x":…,"y":…}` (to the view hit-tested there),
`{"op":"hit","x":…,"y":…}` (which windows and views, Chromium's included, are under a point), `{"op":"clickTitle","title":…}` (clicks the
window's control showing that text, a sidebar row…), `{"op":"appearance","value":"dark"}` (`light`, `system`), `{"op":"settings","pane":"tabs"}` (the Settings window on a page), `{"op":"peek","value":true}` (the hidden sidebar as a floating panel), `{"op":"quit"}`. `run` replies with the command's main-thread time.
Any request may add `"private": true` (or `false`) to act on the first private (or normal) window, or `"flag": "…"` to act on the
last window with that flag (a mini window: `"mini-window"`). Socket paths must be short (< 104 bytes): use a relative path and launch from that
directory.

End-to-end tests: `./forkctl test --e2e` builds the app and runs `Tests/E2E` against the selected engine
(`AppDriver` + `TestHTTPServer` in `Testing/`).

## Non-negotiables

- Do not animate the web view's frame (engines may host pages in child windows); animate overlays.
- Performance: one `@Observable` per tab; sidebar rows come from `TabStore.rows` (cached by structure
  version). Heavy work never runs in `activate()`.
- Privacy: no Google/third-party service is contacted unless the user chose it (search engine,
  suggestions are opt-out settings and default to DuckDuckGo). An idle browser contacts nobody (E2E net-log
  test). The one background contact is ad-blocking list updates (easylist.to, GitHub), started only once the user
  browses and turned off with `adblock.enabled`. Extension updates go to the Chrome Web Store for store installs.
